nexa-mfrr-nordic-eam

Python library for building and submitting mFRR energy activation market bids to Nordic TSOs.

Python library for building, validating, and serialising mFRR energy activation market (EAM) bids for the four Nordic TSOs: Statnett (Norway), Fingrid (Finland), Energinet (Denmark), and Svenska kraftnat (Sweden).

What it does

The Nordic mFRR energy activation market went live on 4 March 2025 as part of the Nordic Balancing Model (NBM). BSPs (Balancing Service Providers) submit bids to their connecting TSO via CIM XML documents over ECP/EDX.

This library handles the BSP side of that workflow:

  • Build simple bids — divisible and indivisible bids with full attribute support
  • Complex bid groups — ExclusiveGroup, MultipartGroup, InclusiveGroup with group-level validation
  • Technically linked bids — TechnicalLink builder prevents double-activation across consecutive MTUs
  • Conditionally linked bids — adjust availability in QH0 based on activation outcome in QH-1 or QH-2
  • TSO configuration — Statnett (NO), Svenska kraftnat (SE), and Energinet (DK) fully configured
  • Validate before you send — common and TSO-configurable rules, pre-MARI and post-MARI price limits
  • Serialise to CIM XML — generates compliant ReserveBid_MarketDocument XML per the NBM schema
  • Timing helpers — gate closure calculations, MTU boundaries, DST handling, MARI vs pre-MARI timing

What it does not do: manage your ECP/EDX endpoint. That is infrastructure you deploy and operate separately. This library generates the XML documents you send through your endpoint.

Quick start

Submit a simple divisible bid to Statnett

from nexa_mfrr_eam import (
    Bid, BidDocument, BiddingZone, Direction,
    MarketProductType, TSO, MARIMode,
)

# Build a 50 MW up-regulation bid
bid = (
    Bid.up(volume_mw=50, price_eur=85.50)
    .divisible(min_volume_mw=10)
    .for_mtu("2026-03-21T10:00Z")
    .resource("NOKG90901", coding_scheme="NNO")
    .product_type(MarketProductType.SCHEDULED_AND_DIRECT)
    .build()
)

# Wrap in a document and target Statnett
doc = (
    BidDocument(tso=TSO.STATNETT)
    .sender(party_id="9999909919920", coding_scheme="A10")
    .add_bid(bid)
    .build()
)

# Validate against Statnett-specific rules
errors = doc.validate(mari_mode=MARIMode.PRE_MARI)
if errors:
    for e in errors:
        print(f"  {e}")
else:
    xml_bytes = doc.to_xml()
    # Send xml_bytes via your ECP endpoint to Statnett

Build a multipart bid (multiple price levels, same MTU)

from nexa_mfrr_eam import MultipartGroup, BiddingZone, Direction, MarketProductType

group = (
    MultipartGroup(bidding_zone=BiddingZone.NO2)
    .direction(Direction.UP)
    .for_mtu("2026-03-21T10:00Z")
    .resource("NOKG90901", coding_scheme="NNO")
    .add_component(volume_mw=20, price_eur=50.00)
    .add_component(volume_mw=15, price_eur=75.00)
    .add_component(volume_mw=10, price_eur=120.00)
    .build()
)

If the highest-priced component is accepted, all cheaper components are also accepted. All components must have different prices.

Build technically linked bids across MTUs

Technical linking prevents double-activation when a bid in one MTU is activated via direct activation and the resource is still ramping during the next MTU.

from nexa_mfrr_eam import TechnicalLink, BiddingZone, Direction, MarketProductType

link = (
    TechnicalLink(bidding_zone=BiddingZone.SE3)
    .resource("REG-OBJ-SE-001", coding_scheme="A01")
    .add_mtu(
        mtu="2026-03-21T10:00Z",
        direction=Direction.UP,
        volume_mw=25,
        price_eur=90.00,
        product_type=MarketProductType.SCHEDULED_AND_DIRECT,
    )
    .add_mtu(
        mtu="2026-03-21T10:15Z",
        direction=Direction.UP,
        volume_mw=25,
        price_eur=90.00,
        product_type=MarketProductType.SCHEDULED_AND_DIRECT,
    )
    .build()
)

Build conditionally linked bids

Conditional linking adjusts availability in QH0 based on what happened in QH-1 or QH-2.

from nexa_mfrr_eam import Bid, ConditionalStatus, BiddingZone

# QH-1 bid
bid_qh_minus_1 = (
    Bid.up(volume_mw=30, price_eur=70.00)
    .divisible(min_volume_mw=5)
    .for_mtu("2026-03-21T10:15Z")
    .resource("NOKG90901", coding_scheme="NNO")
    .build()
)

# QH0 bid: unavailable if QH-1 was activated
bid_qh_0 = (
    Bid.up(volume_mw=30, price_eur=70.00)
    .divisible(min_volume_mw=5)
    .for_mtu("2026-03-21T10:30Z")
    .resource("NOKG90901", coding_scheme="NNO")
    .conditionally_available()
    .link_to(bid_qh_minus_1, status=ConditionalStatus.NOT_AVAILABLE_IF_ACTIVATED)
    .build()
)

Domain context

The mFRR EAM operates on 15-minute Market Time Units (MTUs). There are 96 MTUs per day. BSPs submit bids to their connecting TSO; the TSO forwards them to the Activation Optimisation Function (AOF), which selects bids for activation.

Pre-MARI gate closure times:

  • BSP GCT: QH-45 (45 minutes before the quarter-hour)
  • TSO GCT: QH-15
  • AOF run: QH-14
  • Activation orders to BSPs: QH-7.5

The library supports both pre-MARI and post-MARI timing configurations via MARIMode.PRE_MARI and MARIMode.POST_MARI. Pre-MARI price limits are -10,000 to +10,000 EUR/MWh; post-MARI will be -15,000 to +15,000 EUR/MWh.

TSO-specific notes

TSO Country Heartbeat Min bid Notes
Statnett NO Yes (T-12, T-7.5, T-3) 10 MW Period shift, faster activation, mFRR-D support
Energinet DK No 1 MW mktPSRType.psrType mandatory; no direct activation until MARI
Svenska kraftnat SE Yes (every 5 min) 1 MW 6-minute cut-off; silent drop of late documents
